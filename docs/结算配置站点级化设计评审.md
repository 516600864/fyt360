## §1 问题定性：为什么「仅平台管理员」是错的

fyt360 是多租户 SaaS，站点是业务的主人（既有铁律：凭据自配 #44、is_owner 可写 #52、平台不碰租户业务）。而结算规则现状：

| 配置 | 存储位置 | 现状权限 | 问题 |
|---|---|---|---|
| 等级档位（元宝兑换价/三跳比例） | `member_level` 表，**无 site_id，全站一份** | `assertPlatform` 403「仅平台管理员」 | 站长无法配置自己站的分销策略 |
| `ingot_rule` 元宝规则 | `platform_config` 平台键 | 同上 | **且是摆设**（见 §3） |
| `withdraw_rule` 提现规则 | `platform_config` 平台键 | 同上 | **钱从各站商户号出，规则却全局**——2026-10-10 改 min_amount=0 实际连坐了 site-a |
| `dist_alloc` 三级分佣开关 | `platform_config` 平台键 | marketing.ts 同款 403 | 同类 |

## §3 方案 A：站点级结算配置

### 3.1 数据层迁移（迁移 045）

**① `member_level` 按站化**（全量复制方案，选它因引擎 JOIN 零改动）：

```sql
-- 1) 加列 + 换唯一约束
ALTER TABLE member_level ADD COLUMN site_id UUID REFERENCES site(site_id);
ALTER TABLE member_level DROP CONSTRAINT member_level_code_key;
ALTER TABLE member_level ADD CONSTRAINT member_level_site_code_uk UNIQUE (site_id, code);
-- 2) 存量 3 行变 site-a 的种子（唯一有数据的站）
UPDATE member_level SET site_id = (SELECT site_id FROM site WHERE code='site-a');
-- 3) 按种子行复制到其余 active 站点（niwo/yanshi/banta/xincao）
INSERT INTO member_level (site_id, code, name, sort, ingot_price, self_rate, direct_rate, team_rate, team2_rate, icon, "desc", status)
SELECT s.site_id, m.code, m.name, m.sort, m.ingot_price, m.self_rate, m.direct_rate, m.team_rate, m.team2_rate, m.icon, m."desc", m.status
  FROM site s CROSS JOIN member_level m
 WHERE s.status = 'active' AND s.code <> 'site-a' AND m.site_id = (SELECT site_id FROM site WHERE code='site-a');
-- 4) member 重绑：user 的站点决定 member 指向哪站的档位行
UPDATE member SET level_id = nl.level_id
  FROM "user" u, member_level ol, member_level nl
 WHERE member.user_id = u.user_id AND ol.level_id = member.level_id
   AND nl.site_id = u.site_id AND nl.code = ol.code;
-- 5) 新站兜底：注册绑 L1 时站点无行 → 触发器级 seed（迁移内给 active 站全 seed，第 3 步已覆盖）
ALTER TABLE member_level ALTER COLUMN site_id SET NOT NULL;
```

**② `platform_config` 加站点维度**：

```sql
ALTER TABLE platform_config ADD COLUMN site_id UUID REFERENCES site(site_id);
-- 唯一约束：平台键 site_id IS NULL 不受 UNIQUE 限制 → 用部分唯一索引
CREATE UNIQUE INDEX platform_config_key_site_uk ON platform_config (key, COALESCE(site_id, '00000000-0000-0000-0000-000000000000'::uuid));
-- 三键复制到每站
INSERT INTO platform_config (key, site_id, value, updated_by)
SELECT k.k, s.site_id, p.value, NULL
  FROM site s
  CROSS JOIN (VALUES ('ingot_rule'),('withdraw_rule'),('dist_alloc')) AS k(k)
  LEFT JOIN platform_config p ON p.key = k.k AND p.site_id IS NULL
 WHERE s.status = 'active'
ON CONFLICT DO NOTHING;
```

**幂等性**：连跑两次 OK（重绑/复制均有 ON CONFLICT 或 WHERE 守卫）。

### 3.4 ingot_rule 从摆设变真实（§2-#4 修复）

- `self_return`（默认 100）：ordersync 两处返元宝按订单站点读配置。
- `invite_reward`(默认 500)：auth.ts 邀请绑定奖励按站点读配置。
- fallback 链：站点行缺失 → 平台键（site_id IS NULL）→ 代码默认。**constants.ts 两个常量降级为 fallback 默认值**。

## §4 风险与防呆

| 风险 | 防呆 |
|---|---|
| member 重绑错站/漏站 | 迁移后断言：每站 member 行数 = member 绑定该站档位行数；member_level 行数 = active 站数 ×3 |
| 迁移中断半态 | 单事务包裹；连跑两次幂等验证 |
| 引擎按站读配置 miss | fallback 链三层（站点行→平台键→代码默认），miss 不炸 |
| 平台键被误删 | 平台键保留为「模板」，站点行独立 |
| 存量佣金流水不可变性 | 历史 commission_flow 不回溯重算，只影响新单 |
