# H5 多站点识别方案评审（决策#48 mini 同构 / 轻量白标路线）

> 状态：**待钦定**（本文档只评审不动手）。前置评估：H5 现状单站硬编码，服务端已全参数化，瓶颈纯在端上与分发层。
> 关联：决策 #48（mini 站点构建期注入）、决策 #27（会话单站）、#40（订单归属只看 site_id）、#44（公众号凭据真相源）。

## §1 现状定性：H5 是「构建期硬编码单站」

**端上真相源一行**（`apps/h5/src/utils/request.js:6`）：

```js
export const SITE_CODE = 'site-a';
```

全 H5 共 6 处消费该常量：

| # | 消费点 | 位置 | 多站后果 |
|---|---|---|---|
| 1 | token localStorage key（`fyt_token_site-a`） | request.js / bootstrap.js | key 已按站点命名，隔离基础已备好 |
| 2 | 公众号 OAuth appid（`/api/auth/mpconfig?site=`） | bootstrap.js | 静默授权用的是 site-a 公众号 |
| 3 | 静默登录（`/api/auth/hlogin` body.site） | bootstrap.js | **跨站脏用户制造机** |
| 4 | 装修数据（`/api/site/config?code=`） | bootstrap.js | 读到 site-a 的装修 |
| 5 | 企微客服（`/api/site/kf?code=`） | utils/kefu.js | 客服串站 |
| 6 | 转链/分享 URL site 参数 | core/link.js、pages/index | 订单归属错站（#40） |

周边事实：

- **服务端已全参数化**：hlogin / mpconfig / site.config / site.kf / link 全按 `?site=code` 或 body.site 收站，零瓶颈。
- **部署单 bundle**：hosting-deploy.mjs 把一份产物传 `mk.fyt360.cn/h5/`；tkl.html（口令落地页，h5-45）**站点无关**（纯剪贴板写入，无任何 site 逻辑），多站不用动。
- **无域名解析**：`site.domain` 只是后台登记字段，服务端无任何 Host→site 逻辑。
- **对照 mini**：决策 #48 已有先例——`FYT_SITE=niwo` 构建 + patch-site.mjs 构建期替换 SITE_CODE，租户 zip 自行上传。H5 无对等机制，等价于 #48 之前的 mini。

**风险定性**：niwo/xincao3 用户现在访问 /h5/ 会被静默登录成 site-a 用户（装修/品牌/商品全读 site-a，订单归属错站）。当前 H5 仅 2 屏（首页+商品详情）未开放给租户，所以还没炸；开放前必须先定方案。

## §2 方案对比（A / B / C / C-轻量版）

### 方案 A：构建期多产物（对齐 mini 决策 #48）

`FYT_H5_SITE=niwo` 构建 → SITE_CODE 编译期注入（vite define）→ 产物按目录分发 `/h5/niwo/`；site-a 保留 `/h5/` 根路径兼容旧链接与已授权用户。

- ✅ 与 mini 同构（心智/脚本统一）、零运行时开销、token key 天然按站隔离、OAuth redirect_uri 不用管 site 参数（pathname 不变）、URL 干净无参数丢失面
- ✅ 改动面最小：3 个文件（见 §4），**服务端 0 改动**
- ❌ 每个开 H5 的站点要构建+部署一次（开站低频，可接受；后续可挂进 provision 流程）

### 方案 B：运行时 URL 参数识别（单 bundle）

`/h5/?site=niwo` 或首屏脚本解析 query 写 localStorage，运行时切换。

- ✅ 一份产物全站通用，新站零构建
- ❌ **硬伤**：① site 参数丢失面大（OAuth 回跳剥参、分享链、直接输域名）→ localStorage 残留上次站点**串站**；② 静默授权前就要知道 site（mpconfig?site= 鸡生蛋）；③ redirect_uri 要手工保参；④ URL 难看且依赖用户不清理链接

### 方案 C：租户自有域名（完全白标）

租户域名（如 `h5.tenant.com`）→ DNS 指向我们 → server 加 Host→site 解析中间件 → H5 运行时按 hostname 解析。

- ✅ 真白标，URL 最干净，大客户增值能力
- ❌ 改动最大：server 中间件 + H5 runtime + 接入层泛路由 + 每站 DNS/证书/微信公众号授权域名配置
- ❌ **租户侧最大摩擦是 ICP 备案**（大陆微信生态硬门槛，接入商须=腾讯云，周期 1~3 周），不是证书

### 方案 C-轻量版：子域名泛解析 + 泛证书 + EdgeOne 按 Host 分发 ⭐（本评审新增）

形态：`niwo.mk.fyt360.cn` → 泛解析 `*.mk.fyt360.cn` → **泛域名证书**（`*.mk.fyt360.cn`，Let's Encrypt DNS-01 自动续期）→ 接入层（EdgeOne）按 Host 路由到对应 H5 产物目录 → server 可选加 Host 解析（或仍靠产物内烘焙 SITE_CODE）。

**证书归属问题的答案**：证书永远不用租户提供——子域名在 `mk.fyt360.cn` 之下，域名所有权在我们，泛证书一张管全站、DNS-01 自动续期全自动；租户唯一动作是在**自己的公众号后台**把子域名加进「网页授权域名」（微信规则，与证书无关，#44 口径：公众号凭据本就是租户自配）。

- ✅ 租户**零证书、零备案、零 DNS** 操作（共享 mk.fyt360.cn 既有备案）
- ✅ 白标体验「够用」：域名仍是平台域，但每站有独立可记忆的入口
- ✅ 与方案 A **共存互补**：分发目录可以仍是 `/h5/{code}/` 产物，子域名只是 Host→目录的路由糖；A 先落地，轻量版后续叠加不返工
- ❌ 我们侧成本：EdgeOne 接入（当前 CloudBase 静态托管证书是控制台手动上传模式，一年一传不可扩展，多租户必须前置 EdgeOne 或 CLB+ACME）+ 泛证书续期守护
- ❌ 自有域名白标仍是空缺（留给完全体 C）

### 对比矩阵

| 维度 | A 构建期多产物 | B 运行时参数 | C 自有域名 | C-轻量版（子域名） |
|---|---|---|---|---|
| 服务端改动 | **0** | 0 | 中间件+解析 | 可选（A 形态 0） |
| 端上改动 | 小（3 文件） | 中且带串站风险 | 中（runtime 解析） | 小（同 A） |
| 新站上线成本 | 构建+部署一次 | 零 | DNS+备案+配置 | 加一条路由/子域 |
| 租户侧成本 | 0 | 0 | **备案+DNS+公众号配置** | 仅公众号授权域名一项 |
| 串站/脏数据风险 | **无** | 高 | 低 | 无 |
| URL 白标度 | 中 | 低 | 高 | 中 |
| 基础设施 | 现有 hosting 即可 | 现有 | EdgeOne+ACME | EdgeOne+泛证书 |
| 与 mini #48 同构 | **完全同构** | 否 | 否 | 完全同构 |

## §3 推荐与路线

**两段式路线（推荐）**：

1. **现在：A 先落地**——H5 才 2 屏、租户 H5 尚未开放，先用最小改动把「多站可用」做对（与 mini #48 同构，产物按 `/h5/{code}/` 目录分发），消除跨站脏数据风险。
2. **H5 开放给租户时：叠加 C-轻量版**——EdgeOne 前置 + 泛解析泛证书 + Host→`/h5/{code}/` 路由。A 的产物形态原样复用，零返工；完全体 C（自有域名）留作大客户增值项，`site.domain` 字段已备好。

**不建议 B**：串站风险与 H5 的静默授权流程天然冲突，省下的构建成本会用脏数据加倍还回来。

## §4 A 方案改造点清单（钦定后执行）

|---|---|---|---|
| 1 | `apps/h5/src/utils/request.js` | `SITE_CODE` 改为编译期注入：`export const SITE_CODE = __SITE_CODE__;`（vite define 替换，缺省 'site-a'） | 低 |

| 3 | `deploy/scripts/hosting-deploy.mjs` | 多产物目录上传：`/h5/` = site-a（兼容存量），`/h5/{code}/` = 各站产物；tkl.html 不动（站点无关） | 低 |
| 4 | 部署脚本说明 + provision 提示 | `FYT_H5_SITE` 用法文档；后续可挂 provision 流程（本批不做） | 低 |

**不做**：server 端任何改动；B 的运行时解析；EdgeOne/泛证书（留给 C-轻量版阶段）。

## §5 验收标准（A 方案）

1. `FYT_H5_SITE=niwo` 构建产物内 grep 不到 `'site-a'` 硬编码，`fyt_token_niwo` 为 token key，全部 API 请求带 `site=niwo`；
2. 线上 `mk.fyt360.cn/h5/niwo/` 可加载，装修数据为 niwo 的（`/api/site/config?code=niwo`），静默授权走 niwo 公众号（前提：niwo 已配 wechat_mp 凭据）；
3. 存量回归：`/h5/`（site-a）旧链接与已授权用户 token 不失效；
4. tkl.html 行为不变（站点无关）；
5. 连跑两次部署幂等。
