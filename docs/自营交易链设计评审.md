# 自营交易链设计评审稿（B 档 / 03+16+17+18 屏）

> 版本 v2.0 · 2026-09-29 · 状态：**已实施 + 需求更正落地**
> 铁律：砍掉复杂方案，只做满足核心需求的最简设计。本文档为「AI 出方案 → D先生批准 → 实施」流程的第一步。

## ⚠️ v2.0 需求更正（2026-09-29，D先生 定稿）

**自营全面移除快递发货电商，仅保留到店团购/核销模式。**

- 背景：系统大量使用插件支付，与微信官方小程序发货信息管理（发货信息录入/API 上报）冲突；
- 影响：自营商品履约方式不再有 express/group 二选一（**恒 group 到店核销**）；收货地址不再在自营交易链采集；物流录入端点（POST /api/admin/orders/:id/logistics）与 C 端物流卡全部移除；`order.logistics_snapshot` 列已 DROP（迁移 025）；
- 数据迁移（025，幂等）：self_goods 统一 group；历史快递自营单归 group、shipped/delivered 回待核销、settled 单缺券补发（GC{orderId}，7 天）；
- 状态文案：paid 自营单 C 端显示「待使用」（原「待发货」）；fulfill_status 只剩 pending → verified 两态；
- 保留面：收货地址页/API（profile/addresses）与画布 27 屏暂保留（ dormant，交易链不再引用），画布下线与否由 D先生 另行定夺。

## 一句话结论

自营交易链 = **单商品立即购买 → 微信 JSAPI 支付 → 订单落库 → 元宝返利**，无购物车、无运费计算（v1 全场包邮）、无售后工作流（仅退款申请记录）。**阻塞项：微信支付商户号未进件**（支付配置表不存在，后台「支付进件」屏 33:3350 只有画布无后端）。

## 3. 改动清单（批准后实施）

### 3.1 迁移 021（幂等）
```sql
ALTER TABLE "order" ADD COLUMN IF NOT EXISTS address_snapshot JSONB DEFAULT NULL; -- {name,phone,region,detail}
ALTER TABLE "order" ADD COLUMN IF NOT EXISTS sku_snapshot  JSONB DEFAULT NULL;    -- {sku_id,spec,price}
ALTER TABLE "order" ADD COLUMN IF NOT EXISTS payment_no    VARCHAR(64) DEFAULT NULL; -- 微信支付单号
CREATE TABLE IF NOT EXISTS site_payment (              -- 站点级微信支付配置（跟 site_id 走，铁律）
  site_id   UUID PRIMARY KEY REFERENCES site(site_id),
  mch_id    VARCHAR(32) NOT NULL,
  mch_key   TEXT NOT NULL,            -- APIv3 key
  serial_no VARCHAR(64) NOT NULL,     -- 商户证书序列号
  cert      TEXT NOT NULL,            -- 商户证书 PEM
  status    VARCHAR(16) NOT NULL DEFAULT 'active',
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### 3.2 Server 新路由 `trade.ts`（挂 /api/trade，requireUser + optionalUser 前置）
| 端点 | 说明 |
|---|---|
| GET /goods/:id | 自营商品详情（仅 status='on' + 本站点；CPS 铁律：仍不落库不缓存） |
| POST /orders | 下单：原子扣 sku 库存（`skus` JSONB 单元素 UPDATE … WHERE stock>=n）→ 建 order(provider='self', status='created') → 微信下单参数返回 |
| POST /orders/:id/pay | 同单重拉支付参数（15 分钟未支付自动关单重开） |
| POST /notify/wxpay | 微信支付回调：验签 → order paid + settled 两态推进 → 佣金/元宝结算（**复用 M2.3 订单同步的结算 CTE 语义**） |
| GET /wxpay/openid-bridge | （如需）unionid 桥接 |

无购物车：`POST /orders` body = `{goods_id, sku_id, num(≤5), address_id}`，一单一商品。

## 4. 结算语义（对齐 M2.3 定稿）

- 自营单无上游佣金：`commission` = pay_price × 自营毛利率（**待定：自营商品后台需新增毛利率字段，或 v1 固定 rate**）
- 元宝返利 = floor(实付 × 10)（元宝口径以 INGOT_PER_YUAN=100 修订后规则为准——**此处需 D先生拍板：自营单元宝是否与 CPS 同规**）
- 佣金三跳按受益人等级，L1 无佣金 —— 与 CPS 完全同构
- paid_at = 回调时间；settled_at = 回调即结算（自营无「平台确认」外部依赖）

## 5. 明确砍掉（v1 不做）

- 购物车 / 多商品合并支付
