# 品牌三轨对账同步设计评审（2026-10-10）

> 状态：**已实施（2026-10-10，D先生 四项裁决全按本文方案 + cid 白名单 2/8/5/6）**。
> 探针实证：`deploy/scripts/probe-act-reconcile.mjs`（对账预演）；E2E：`deploy/scripts/verify-brand-sync.mjs`（连跑两次全绿）。

## 0. 一句话

每日定时拉蚂蚁活动清单 + fasttype 目录，与 `brand_action_cfg` / schema 楼层引用对账：失效自动禁用（幂等可逆）、未映射与新活动出报告、人工动作全部复用现有 admin-37 —— **不做确认页面**。

## 1. 背景与探针实证（2026-10-10 17:40 实测）

| 事实 | 数据 |
|---|---|
| 上游活动变动频繁 | actlist 两周 193 → 223（+30） |

## 2. 目标 / 非目标

**目标**
- G1 活动（actid）失效自动发现 → 自动禁用，杜绝点击失败（当前 meituan_08 即案例）
- G2 新活动/未映射活动每日 diff 出报告，供运营在 admin-37 补映射
- G3 schema 楼层 cid 引用失效检测出报告
- G4 全程幂等、可重跑、不碰任何业务订单数据

**非目标**
- ❌ 不自动建品牌行（launch 行是「名册品牌↔活动」语义映射，016 人工直配；自动灌 193 活动会污染名册）
- ❌ 不动 plugin/halfscreen 轨（D先生：变动可能性很小）
- ❌ 不做确认页面（人工动作复用 admin-37）
- ❌ 不自动禁用/改动 schema 楼层（报告制，楼层是各站运营资产）

## 3. 设计

### 3.1 对账范围（双域）

**域 1 · actlist 活动对账（自动写库，仅 launch 行）**
1. 拉全量 actlist（翻页以 total 为准，复用 fetch-actlist.mjs 逻辑）
2. `SELECT ... WHERE enabled AND miniapp_cfg->>'mode'='act'` 得 125 行
3. 行的 actid ∉ 上游集合 → `enabled=false, health_status='down'`（UPDATE RETURNING，不删行）
4. 上游 actid 集合 vs 库内已映射集合 diff → 未映射清单
5. 结果摘要写 `platform_config`（key=`brand_sync_state`，jsonb：{ran_at, total, dead:[...], unmapped_count, unmapped_sample:[...≤30]}）

**域 2 · fasttype 引用校验（只读报告）**
1. `fetchFasttype()` 取目录（复用既有缓存与守卫）
2. 校验 `admin_schema` draft+publish 全部楼层 props 中的 `cid`（递归提取数字字段）是否仍在目录
3. 失效 cid 写入 brand_sync_state 报告，不自动改楼层

### 3.2 防呆（关键风险对冲）

| 风险 | 对策 |
|---|---|
| 上游残缺响应（假下架→全库误禁） | actlist `total < 50` 或 fasttype 条目 `< MIN_FASTTYPE_ENTRIES`（沿用 haojingke.ts 既有阈值思路）→ 本轮放弃，写 skipped 状态 |
| apikey 缺失/失效 | 取 provider_config('mayixingqiu')；status≠active 或空 → skip 并记录 |
| 重复禁用抖动 | 只禁 `enabled=true` 的行；禁用动作幂等，重跑无副作用 |
| 自动行/手工行混淆 | 加列 `sync_source VARCHAR(8) DEFAULT 'manual' CHECK IN ('manual','auto')`；自动禁用只碰 `sync_source='auto' OR miniapp_cfg->>'mode'='act'` 的行 |

### 3.3 迁移 SQL（幂等草案，编号顺延）

```sql
-- 0XX: 品牌对账 sync_source 列
ALTER TABLE brand_action_cfg ADD COLUMN IF NOT EXISTS sync_source VARCHAR(8) NOT NULL DEFAULT 'manual';
-- 回填：现有 mode=act 的 launch 行标记为 auto（历史人工直配行为 auto 语义=上游驱动）
UPDATE brand_action_cfg SET sync_source='auto' WHERE miniapp_cfg->>'mode'='act' AND sync_source='manual';
-- platform_config 报告位（如该表无 schema 约束则仅应用层保证 key 唯一）
```

### 3.4 Job 与部署

- `server/src/jobs/brand-sync.ts`：导出 `runBrandSync(site?)`，平台级（无租户维度）
- `server/src/routes/jobs.ts`：`POST /api/jobs/brand-sync/cron?token=`（复用既有 cron 鉴权模式）+ admin 手动触发口
- `function-deploy.mjs` JOBS 注册表加一行：`brand-sync-timer`，每日 07:30（北京时间，错开 ordersync 30 分钟点）
- dry-run：`?dry=1` 只出报告不写库（首次上线先 dry 跑人工核对）

### 3.5 报告出口（不做页面）

- 常态：platform_config.brand_sync_state（admin-37 列表头可选加只读角标「上次对账 xx-xx · 失效 n · 未映射 m」，本次不做，留待办）
- 异常：job 结果含失效行时 console.warn（云托管日志可见）
