## 2. 页面实现流程（开发会话标准动作）

实现/修改某个页面时，按固定四步走：

1. **查稿**：在上表找到屏号 → 打开 `screens/` 对应 PNG；需要看交互细节/取色/量尺寸时，用 ardot 工具直接读画布节点（batch_read / 截图）；
2. **实现**：按三端 token 文件写样式（见 §4），不硬编码色值；
3. **验收**：构建后截图（或浏览器/开发者工具截图）与设计稿 PNG **并排对照**，布局、色值、文案口径一致才算过；
4. **回填**：实现完成后更新本表「目标页面」列。

## 3. 设计变更流程（改设计 ≠ 改代码）

开发中发现设计不合理时，**禁止直接在代码里偏离设计**，走闭环：

```
发现设计问题 → 画布上改设计稿（记录原因）→ 需求文档补决策/改口径
→ 重新导出该屏 PNG 覆盖 screens/ 对应文件 → 再改代码
```

快照文件与画布节点一一对应，**每次画布改动后必须重导该屏**，否则快照失真。

## 4. Token 溯源（规范源头 vs 实现载体）

- **规范源头**：设计系统画布 `3:34`（`design-system.png`）+ 需求文档 §5（VI 波普风：玫红 `#E8336D` / 鎏金橙 `#FFAA1D` / 奶油白 `#FFF6E9`，粗描边、ZCOOL QingKe HuangYou 标题字）；
- **实现载体**（三端独立文件，刻意不抽共享包——技术形态不同、抽象收益不抵成本）：
  - 小程序：`apps/mini/src/styles/tokens.scss`（SCSS 变量）

- **改主题色/间距的唯一路径**：改设计系统画布 → 同步改三个 token 文件 → 全站生效。组件代码里不许出现裸色值。
